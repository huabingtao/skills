# danke-content-creator-skill

专为《弹壳特攻队》游戏攻略打造的内容创作 Skill。分析用户提供的原始素材（活动截图、活动文本、奖励表格等），按照结构化模板自动撰写高规格初稿 `攻略.md`。

## 🛑 去 AI 味与排版铁律 (Anti-AI Writing Rules)

1. **【严禁标题使用 Emoji 图标】**：大标题（H1）、小章节（H2/H3）一律使用纯中文/英文（例如 `## 一、 活动介绍`、`## 二、 觉醒机制与核心质变`），严禁携带任何 Emoji 图标（如 🦁、🐾、🌟、💡、📋、🌈 等），保持极简专业。
2. **【彻底消除 AI 模板化列表结构】**：严禁使用 `1. **小标题**：内容` 或 `1. **觉醒红1星（基础门槛）**：` 这类机械的数字加粗冒号结构。必须直接采用无序列表（`-`）结合大白话自然叙述。
3. **【拒绝 AI 夸张修饰与空洞套话】**：严禁出现“白嫖”、“基础面板非常扎实”、“宠物体系发动机”、“实战提升巨大”、“不难看出”等 AI 惯用废话，只陈述清晰客观的机制、数值与游戏事实。
4. **【三大字数黄金档位精算】**：后续所有文章撰写与生成，必须严格对应以下 3 个字数节点之一（结合文末固定尾块字数，精准对齐微信公众号文中广告触发门槛）：
   - **档位一：1 ~ 300 字（极短快讯 / 话题竞猜档）**：无需广告，短平快直击重点；
   - **档位二：550 字左右（单条文中广告黄金档 ⭐）**：适合高频问答 FAQ、月度大事件日历、特工/技能评测，稳定支持插入 **1 条文中广告**；
   - **档位三：850 字左右（双条文中广告深度档 ⭐⭐）**：适合大活动阶梯方案精算、全体系深度测评攻略，稳定支持插入 **2 条文中广告**。

## 活动攻略的事实与预算工作流

- 补充或修改已有文章前，重新读取磁盘上的 `攻略.md`，保留用户手动编辑；不从聊天旧版本重建整篇。
- 先梳理用户截图和文字中已确认的活动时间、玩法是否自动、道具来源、实测消耗与进度、过程掉落、目标档位及兑换顺序。过程掉落与进度条奖励分开；个人掉落经历不能写成已确认保底机制。
- 每个方案明确写一行 `累计奖励：神器核心自选 ×1、月咏动态头像 ×1。`，按已确认资料列完整累计奖励及数量。新增方案时同步标题、摘要、正文和补钻表；未知奖励先核算预算，向用户补齐信息，不能自行猜奖。
- 数值先交给 [活动预算计算器](references/activity_budget.md)，再写初稿或发送预算进展。使用原始实测分数计算，目标道具向上取整，补钻使用整数缺口；初始赠送只加一次，实测库存不重复并入全期产出。
- 不预填广告、礼包、商店返还或未提供的开箱节点；不把某期的任务总数、600 箱上限和转化比例复用为其他活动事实。沿用用户本期已明确的开箱建议。
- 钻石表格把单位写在对应列的表头，例如 `补至 1000（钻石）`，数据格只写数字；正文中的单位正常保留。
- 普通图标保持 `完整名称{{short}}`，例如 `神器核心自选宝箱{{神器核心自选}}`。short 查排版技能的 `packs/danke/image_mapping_short.json`，同图只推荐一个；旧长宏兼容，正文名称不随宏缩写。先核对映射，未知图标保留名称，不输出空图，也不借用未确认的道具图标。
- 用户给出活动内截图时，制作封面优先采用其中可识别的活动场景、角色与玩法元素，参见 `wechat-cover-generator`；通用 `article-top` Banner 与活动封面分别处理。

公众号草稿更新后，其他平台切图必须从本次最新编译 HTML 重新生成；微信回读图片兼容 `src` 和 `data-src`。抖音沿用有头审核交接，是否点击发布以用户当次要求为准。

抖音默认交给同级 `douyin-publisher-skill` 的奶白紫色模板，每个方案独立成图；具体流程见该技能 `references/card_workflow.md`。卡片与正文引用同一次核算，依次填写目标进度、完整累计奖励、补钻预算、操作建议及估算依据，保留“预计”和样本限制。派生卡片不改写公众号正文；用户明确选择旧版时才使用 `article-to-img-skill --profile douyin`。

### 配图与文末配置

- 装备、道具、技能、宠物配图优先使用已登记的 `{{short}}`，如 `科技滑板碎片{{滑板碎片}}`；本来简短的名称可同名使用，如 `双绝枪{{双绝枪}}`。旧长宏仍可用。不要手写编译后的图片语法，不默认添加 `grid2`、`center`、宽度和 `caption`。
- 只有用户明确要求大图、并排图片，或截图文字需要放大阅读时，才使用完整图片语法；顶部 Banner 沿用下方规则。
- 往期推荐和公众号二维码只在 Frontmatter 配置 `recommendations`、`qrcode_image`，由排版技能自动生成文末区块。正文不要添加 `{{往期推荐}}`、`{{往期精彩推荐}}`、`{{扫码获取更多精彩}}`，也不要重复手写推荐区或二维码图。
- 不需要时用 `recommendations: []`、`qrcode_image: false`；字段省略时也不生成对应区块。

## 语言与格式规范

1. **中英文空格**：中文与英文 / 数字之间**必须添加一个空格**（例如：`[活动名] 攻略`、`300 钻石 / 张`、`[X] 进度`、`S 级装备`）。
2. **自然去 AI 味**：删除僵硬连接词（“综上所述”、“此外”、“重磅开启”），使用通俗、干货、亲切的老玩家交流口吻。

3. **段落简洁**：写完机制、条件和操作即可结束小节，不固定追加总结句、道理或重复提醒。保留影响结论的必要限制，不用套话凑字数。
4. **成长路线按达成阶段排列**：前中期可以达成的搭配放在前中期，不因涉及神铸就放到神炼之后；系统解锁条件与推荐培养节点分开说明。
