# 弹壳礼包码兑换

## 输入与范围

需要明确的礼包码、玩家 ID 文件和结果位置。用户要求兑换即已授权对这些 ID 请求兑换接口；仅优化技能或检查文件时使用 `--dry-run`，不执行真实兑换。不自行扩展玩家名单或礼包码。

- TXT：UTF-8（支持 BOM），每行数字 ID，或 `备注-数字ID`；空行、`#` 注释忽略。
- CSV / XLSX / XLS：识别 `ID`、`玩家ID`、`userId`、`用户ID`、`游戏ID`，大小写不敏感。找不到使用第一列并告知。CSV 必须有表头。
- 去重保序，保留文本前导零。表格里的 `123.0` 可还原为 `123`，小数、科学计数法及其他非法文本拒绝；Excel 已丢失的数字精度无法恢复，应将长 ID 存为文本。

## 执行

从技能仓库根目录运行；其他目录使用脚本绝对路径。Python 依赖见本技能 `requirements.txt`。TXT/CSV 预检无需 OCR 或 pandas；Excel 读取和 XLSX 报告需要 pandas 与对应 Excel 引擎。

```bash
# 先离线预检，报告中各条状态为待兑换
python3 skills/danke-redeem-skill/scripts/redeem.py --file /输入/ids.csv --code '用户提供的兑换码' --output /输出/dist/redeem_preview.csv --dry-run

# 已获用户授权后，使用单独结果文件执行
python3 skills/danke-redeem-skill/scripts/redeem.py --file /输入/ids.csv --code '用户提供的兑换码' --output /输出/dist/redeem_report.xlsx --delay 0.5
```

输出支持 `.csv` 和 `.xlsx`；`.xls` 仅支持输入。脚本先验证报告可写，再加载 OCR 和请求接口；每条开始前记录“待核实”，收到结果后原子更新报告。报告路径应独立于输入文件，重复任务选择新的报告名以保留历史。已有报告默认拒绝覆盖，只有明确要求覆盖才使用 `--force`；输入与输出同一路径始终拒绝。

中断后保留成功、已领取、失败、待核实、待兑换状态；不要把“已领取”算本次新增成功。恢复任务时先读取报告，仅选择需要重试的 ID；待核实表示请求可能已到服务端，需核对后处理。失败使用非零退出码，不以进程结束当作全部成功。

兑换请求超时或响应无法解析时标记“待核实”，不盲目重发领取请求。验证码失败有限重试，间隔遵守 `--delay`；非负有限秒数才有效。这里只在本地识别验证码；不把玩家名单交给第三方 OCR。

## 交付

报告总数、成功、已领取、失败/待核实数、耗时与报告路径。没有取得成功响应的条目不能报告已兑换。任务产物、名单和真实结果不提交到技能仓库。
